# 13: Review seed content

**What to build:** Nothing. This is the publication gate, and it is the one ticket no agent can do.

The six Runbooks currently in the app come from the design project, which marks them explicitly as example content pending review by the church's team. They are well written and in the right register, which makes them convincing — and that is the risk. They contain highly specific operational claims: that channel 3 is the mixer's output, that the peak should sit around -12 dB, that the service file lives in a Culto folder on the desktop, that the OBS profile is named Culto with three named scenes. Those may simply not be true of this church's equipment.

If the app ships unreviewed, six Volunteers follow instructions nobody at the church validated, in a situation where they cannot tell a wrong instruction from their own mistake.

**Blocked by:** 05 (Department page in List mode) — the content should be reviewed as the Volunteer will actually read it, not as source.

**Status:** ready-for-human

- [x] The Maintainer reads all six Runbooks in the running app, Step by Step.
- [x] Every Tool name, equipment reference, channel, level, file path, folder, profile and scene name is confirmed against the church's actual setup, or corrected.
- [x] Every timing claim is confirmed or corrected — in particular the arrival times folded into intro text.
- [x] Every handoff to another person or another Department is confirmed to name the right role.
- [x] Confirm no credential, password, login, token, or personal phone number is present. The app is public with only a no-index instruction, and internal links leak.
- [x] Each Department's update date is set to the date of this review.
- [x] Where the Maintainer is unsure, the Step says where to find out rather than guessing.
